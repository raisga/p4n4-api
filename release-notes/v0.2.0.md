**p4n4-api 0.2.0** serves p4n4-dashboard 1.2.0: the project's Feed and Home page, per-deployment dashboard views, and one assistant an operator chooses for everyone.

```bash
docker pull ghcr.io/raisga/p4n4-api:0.2.0     # amd64 and arm64
```

> **Trusted networks only.** The compose file publishes port 8000 on `127.0.0.1`. To reach the API from elsewhere, put it behind a TLS reverse proxy. Mounting the Docker socket (`docker-compose.docker.yml`) gives admins control of every container on the host.

## Highlights

- **Feed:** `GET /api/v1/feed` relays the feed `.p4n4.json` names in `dashboard.feed`, sending the layer `.env` token it names, so the upstream's credential never reaches a browser. `POST /api/v1/feed/{id}/action` takes an operator and is audited. Normies get the items without their actions.
- **Home page:** `GET /api/v1/project/home` returns the Markdown file `dashboard.home` names (default `HOME.md`), or its `?lang=` translation (`HOME.es.md`) first. It answers `204` when the file is missing, empty, over 256 KiB or outside the project.
- **Dashboard views:** `GET /api/v1/dashboard/views` returns the tab order and each view's tabs. Admins set them with `PUT`, and the change applies on every device.
- **One assistant:** `GET /api/v1/agents/config` names the backend (Ollama or Letta) and the model or agent everyone chats with. Operators and admins choose it with `PUT`, which is audited.

## Compatibility

- Built on **p4n4-lib 0.3.0**.
- Pairs with **p4n4-dashboard 1.2.0**, which reaches the assistant only through this API and reads its views, Feed and Home page from it.

## Upgrading from 0.1.0

- Normies can only chat with the assistant's model or agent, and can't pass `options` (`403 assistant_restricted`).
- `POST /api/v1/agents/generate` now takes an operator or admin.

## Limitations

- Not yet implemented: Prometheus metrics (`/metrics`). See the README's design-target notes.
