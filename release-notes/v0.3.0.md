**p4n4-api 0.3.0** serves p4n4-dashboard 1.3.0: settings for each dashboard view, a banner, tools for managing accounts, the project's chats and vision overlay, and the edge inference runner in the ai layer.

```bash
docker pull ghcr.io/raisga/p4n4-api:0.3.0     # amd64 and arm64
```

> **Trusted networks only.** The compose file publishes port 8000 on `127.0.0.1`. To reach the API from elsewhere, put it behind a TLS reverse proxy. Mounting the Docker socket (`docker-compose.docker.yml`) gives admins control of every container on the host.

## Highlights

- **View settings:** `GET/PUT /api/v1/dashboard/view-settings` keeps what else the power and normie views show: the tab each opens on, Home's cards, its own Grafana page, its cameras and their vision overlay, and which alerts pop up and chime. Everyone signed in reads them; admins change them, and each change is audited. Like the views, they're presentation: the API still decides what each role may read.
- **Banner:** `GET/PUT /api/v1/dashboard/banner` holds a message for every dashboard view, `info` or `warning`, until an admin clears it or its `until` time passes. Changes are audited.
- **Account tools for admins:**
  - `POST /api/v1/users/{username}/sign-out` ends every sign-in of a user and keeps their password.
  - Users now carry `last_login_at`.
  - `must_change_password` (on create, or with a password reset) makes a user choose a new password before anything else. Their token response says `password_change_required: true`, and every route outside `/api/v1/auth/*` answers `403 password_change_required` until `POST /api/v1/auth/password`.
  - On the command line: `p4n4-api users sign-out`, and `--must-change` on `users add` and `users passwd`.
- **Chats:** `GET /api/v1/chats`, `POST /api/v1/chats/codes` and `DELETE /api/v1/chats/{id}` let admins link and unlink the chats a project's bot serves (e.g. on Telegram). The API relays the service `.p4n4.json` `dashboard.chats` names, sending the layer `.env` token it names, so that credential never reaches a browser. Codes and unlinks are audited.
- **Vision overlay:** `GET /api/v1/project/vision` serves the JSON file `dashboard.vision.file` names: labels, alert rules, and each camera's recorded boxes and behaviours. It adds `dashboard.vision.live` as `live`, and answers `204` when there's none, or the file is missing, invalid, over 8 MiB or outside the project.
- **Edge runner in the ai layer:** inference, the edge metrics' `inference_ms` and the AI events bucket follow the runner wherever the project runs it. That's the ai layer's `ei-runner` profile, or a legacy edge layer.

## Compatibility

- Built on **p4n4-lib 0.4.0**; the image installs it from PyPI.
- Pairs with **p4n4-dashboard 1.3.0**, which reads its view settings, banner, chats and vision overlay, and shows the password form `password_change_required` asks for.

## Upgrading from 0.2.0

- The database migrates on first start: it adds `last_login_at` and `must_change_password` to users. Back up the `p4n4-api-data` volume first.
- Token and `GET /api/v1/auth/me` responses gain `password_change_required`.
- Don't require a new password from someone whose dashboard is older than 1.3.0: it has no form for it, so every request would get `403` until they change it some other way (`POST /api/v1/auth/password`).
- Projects migrated with `p4n4 migrate edge` find their runner in the ai layer; projects that still have an edge layer keep working.

## Limitations
